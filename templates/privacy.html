What happens to the file you upload

Your file is used to create your analysis and nothing else. The results live only in this server's memory, only for your session, and are gone when you clear them, after {{ store_stats.idle_timeout_minutes // 60 }} hours without activity, or when the server restarts.

Is my file stored?

No. The upload is written to a temporary file only long enough to read it, because a CSV reader needs something to read, and that file is deleted before the request finishes, whether the analysis worked or not. What remains is the analysis, held in an in-memory database that never touches the disk.

Who can see my data?

Nobody else using the site. Your browser holds one cookie: a random identifier, signed so it cannot be forged, that says which workspace in memory is yours. It carries no data of its own.

When is it deleted?

After {{ store_stats.idle_timeout_minutes }} minutes without a request, your workspace is dropped. Pressing Clear this data on the upload page drops it immediately. Restarting the server drops all of them.

Does anything leave this machine?

Your data does not. There are no analytics, no outbound API calls and no accounts. The browser fetches a web font from Google Fonts and the map library and outlines from public code hosts, and none of those requests carry anything about your supply chain. City lookups run against a GeoNames extract bundled with the code.

What this does not claim

The server can read your data while it is analysing it. It has to: it is the thing doing the analysis. Anyone with access to the running process could in principle read what is in its memory. Making that untrue would mean encrypting the file in your browser and doing the whole calculation there, which is a different and much larger piece of software.

So the honest version is the one above: nothing is stored, nothing is shared between visitors, nothing is sent anywhere, and the window in which it exists at all is your session.

Limits worth knowing

  • Uploads are capped at {{ max_mb }} MB and must be CSV.
  • The server holds at most {{ store_stats.limit }} sessions at once. Past that the least recently used one is dropped, which costs that visitor their upload and nothing else.
  • Right now it is holding {{ store_stats.live }} workspace{{ "s" if store_stats.live != 1 }} in memory.

All of this is in optimizer/store.py and the upload handler in app.py, which are about a hundred lines between them and are worth reading rather than believing.
