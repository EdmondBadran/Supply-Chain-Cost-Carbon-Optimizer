Privacy

What happens to the file you upload

Your order data is loaded into a database that exists only in this server's memory, only for your session. It is never written to disk, never shared with anyone else using the site, and it is gone when you stop using it or when the server restarts.

Step by step

  1. The upload arrives and is written to a temporary file, because a CSV parser needs something to read. That file is deleted before the request finishes, whether the load worked or not.
  2. The rows are turned into a graph of locations and routes in an in-memory SQLite database that belongs to your browser session alone. Nothing about it touches the filesystem.
  3. Your browser holds one cookie: a random identifier, signed so it cannot be forged, that says which workspace in memory is yours. It carries no data of its own.
  4. After {{ store_stats.idle_timeout_minutes }} minutes without a request, your workspace is dropped. Pressing clear this data on the data page drops it immediately. Restarting the server drops all of them.

What leaves this machine

Your data does not. There are no analytics, no third-party scripts, no outbound API calls and no accounts. The one thing the browser fetches from elsewhere is a web font from Google Fonts, which is a request for a font file and carries nothing about your supply chain. Geocoding runs against a GeoNames extract bundled with the code, so looking up a city never asks anyone anything.

What this does not claim

The server can read your data while it is analysing it. It has to: it is the thing doing the analysis. Anyone with access to the running process could in principle read what is in its memory. Making that untrue would mean encrypting the file in your browser and doing the whole calculation there, which is a different and much larger piece of software. Saying "not even we can see it" without having built that would be a claim that falls apart the moment somebody asks how it works.

So the honest version is the one above: nothing is stored, nothing is shared between visitors, nothing is sent anywhere, and the window in which it exists at all is a few minutes of memory.

Limits worth knowing

  • Uploads are capped at {{ max_mb }} MB and must be CSV.
  • The server holds at most {{ store_stats.limit }} sessions at once. Past that the least recently used one is dropped, which costs that visitor their upload and nothing else.
  • Right now it is holding {{ store_stats.live }} workspace{{ "s" if store_stats.live != 1 }} in memory.

All of this is in optimizer/store.py and the upload handler in app.py, which are about a hundred lines between them and are worth reading rather than believing.
