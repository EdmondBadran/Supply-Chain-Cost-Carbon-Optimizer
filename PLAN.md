# Build plan

Stages are meant to be done in order, each confirmed before the next starts.

## Stage 0 - project setup
- [x] CLAUDE.md, PLAN.md, MEMORY.md, ERRORS.md
- [x] .gitignore, git init
- [x] grilling round + end-state mockups agreed before building

## Stage 1 - data model and sample dataset
- [x] Graph-shaped schema, not a fixed topology: nodes (warehouse, supplier,
      customer region), edges (route between two nodes), sized by whatever
      the CSV contains - works for 3 nodes or 300
- [x] Node fields: city + country (for geocoding), type, weight/volume handled per order
- [x] Edge fields: order volume, transport mode, return rate
- [x] Bundle a global city -> lat/long reference table (GeoNames cities15000,
      34,135 cities across 244 countries, no external API), plus accept
      lat/lon columns directly in the CSV for anything the table misses
- [x] Build one realistic sample CSV set - 1,307 orders, 4 warehouses,
      32 destination cities across 6 continents, generated by a seeded script
      that validates every city against the reference table before writing
- [x] SQLite schema + loader with real CSV validation (missing columns,
      unknown cities, bad numbers, unknown transport modes) - bad rows are
      reported with line numbers, not fatal

## Stage 2 - CSV upload / ingestion
- [ ] Flask app skeleton
- [ ] Upload page (CSV) with validation and clear error messages
- [ ] Parse CSV into the node/edge graph in SQLite via pandas

## Stage 3 - cost-to-serve engine
- [ ] Per-edge (route) cost: shipping by transport mode, warehouse handling/
      storage allocated by weight/volume, returns cost
- [ ] Roll up by node (warehouse/region) and by customer
- [ ] Flag high-cost outliers

## Stage 4 - emissions engine
- [ ] Distance per edge: geocode zip/city via the bundled reference table,
      haversine formula between the two nodes
- [ ] Per-edge emissions: transport (distance x mode factor), packaging, warehouse energy share
- [ ] Roll up by node and by customer
- [ ] Flag high-carbon outliers

## Stage 5 - bottleneck scoring
- [ ] Score every node/edge on cost+carbon overlap (the "quick win" logic) -
      untagged items rank on cost+carbon only
- [ ] Effort tag (low/med/high) settable per flagged item, factored into score
      once set, persisted in SQLite
- [ ] Sanity check against the sample dataset (flags should look plausible)

## Stage 6 - network map
- [ ] Render the graph on a map: nodes placed by geocoded location, edges as
      lines colored by transport mode
- [ ] Bottleneck flags shown directly on nodes/edges (not just in a table)
- [ ] Click a node or edge to open a detail panel: cost, carbon, effort tag

## Stage 7 - what-if editing
- [ ] Change transport mode on an edge, reassign a region to a different
      existing warehouse - recalculate cost/carbon live
- [ ] Show the delta: "this change saves $X and Y tons CO2"
- [ ] Not in v1: adding/removing nodes (needs reassignment + capacity logic,
      deferred until the toggle/reassign version is proven out)

## Stage 8 - polish and demo readiness
- [ ] Sample dataset loads by default on first run
- [ ] README (human-voiced, setup + usage)
- [ ] Pass through for edge cases (bad CSV, missing columns, empty upload)
